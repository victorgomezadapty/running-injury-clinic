# Milestone 1 methodology

The analysis is descriptive and cross-sectional. It investigates what is available and who can provisionally enter a running cohort. No biomechanical group-effect estimates, joint-angle reconstruction, causal inference or predictive models are produced.

## Processing sequence

1. Acquire the pinned Figshare API snapshot, both original CSVs and README with file integrity checks. Read archive directories with HTTP ranges.
2. Read every source metadata field as text in UTF-8, preserving spelling and identifiers. Append normalized text, numeric, timestamp and provenance columns.
3. Recover missing timestamps from well-formed filenames with an explicit provenance flag. Join tasks on participant + filename only. Audit shared metadata disagreements.
4. Report all-person earliest observations, earliest running observations, walking earliest observations and all running rows separately. Avoid treating repeated observations as independent people.
5. Profile raw missingness, unknown/placeholder values, numeric plausibility flags, repeated timestamps/days and injury-status/diagnosis changes. Do not replace missing injury information with healthy labels.
6. Build observation-level candidate inclusion/exclusion reasons, then select the earliest eligible row per participant. Retain original observations for sensitivity analyses.
7. Open ten JSONs sequentially. Record shape, sampling rate, marker names, expected-field gaps, non-finite coordinates, zero XYZ frames and calculated-field paths. Do not compute movement features.
8. Export plain CSV tables and static PNG charts. A small metadata cache uses CSV to keep the base environment simple; Parquet is appropriate for later larger feature caches, with a separately recorded schema and source/version hashes.

## Statistical units and denominators

Participant counts and distributions use one explicitly selected observation per person. Ever-recorded diagnosis counts deduplicate person–diagnosis pairs across sessions and primary/secondary fields; their totals can exceed the number of runners. All-row summaries are sensitivity/context outputs. Missingness denominators are stated in table names and report text; missing cells and implausible nonmissing entries are separate quantities. Injury duration is additionally summarized among injury-positive first running records.

## Future analysis requirements

Check speed overlap before attributing a biomechanical group difference to injury. Examine age, self-reported gender, anthropometry, experience and activity level with a prespecified adjustment strategy. Diagnose missingness and complete-case selection. Repeated observations require participant-aware inference/validation. Report group contrasts, uncertainty, effect sizes and distribution overlap; define multiple-comparison and sensitivity plans before inference. Stable statistical clusters need biomechanical interpretation and adequate size before being called clinical phenotypes. All preprocessing for future model validation must occur inside participant-grouped training folds.

## Complementary source boundary

The external interlaboratory benchmark is separately namespaced and profiled now. It can inform protocol compatibility and later sensitivity design. It does not increase the primary cohort or fill missing Calgary fields. Possible overlap with the Calgary source prevents claiming independent validation without a verified crosswalk. See `complementary_sources.md` and `external_compatibility.md`.

## Reproducibility

The report is regenerated by a single offline command. Source checksums, installed package versions and archive indices are saved. Notebooks call src functions instead of duplicating cleaning logic. No source file is overwritten. Regression checks cover source sizes/checksums, participant/task counts, injury-status edge cases, repeated-person selection and JSON linkage. Re-run only affected checks after changes. Review all figures visually before delivery.
